================================================================================
RDFGRAPHGEN - SHACL-based RDF Generator
================================================================================

Tool Information:
  Name: RDFGraphGen
  GitHub: https://github.com/cadmiumkitty/rdfgraphgen
  PyPI: https://pypi.org/project/rdf-graph-gen/
  Type: SHACL shape-based RDF generator
  Purpose: Generate RDF data conforming to SHACL shape constraints
  Schema: lubm_shacl.ttl (LUBM ontology as SHACL shapes)
  Location: RDFGRAPHGEN/ directory
  Script: execute_benchmark.py

Technical Details:
  Language: Python
  Input: SHACL shape definitions
  Output Format: Turtle (.ttl)
  Key Feature: Scale factor controls data volume
  Dependencies: rdf-graph-gen Python package

SHACL (Shapes Constraint Language):
  - W3C standard for defining RDF constraints
  - Defines shapes (classes), properties, datatypes, cardinalities
  - Validation and constraint language
  - Unlike SPARQL, focuses on SHACL conformance

Name: RDFGRAPHGEN_LUBM_HIGH_COHERENCE
Goal: High scale factor ensures complete shape conformance

Parameters:
  shape: lubm_shacl.ttl              # LUBM schema in SHACL format
  scale_factor: 3000                 # KEY PARAMETER - Higher scale
  runs: 10                           # Number of experimental runs

  Command: python3 RDFGRAPHGEN/execute_benchmark.py --scale-factor 3000
  Or: ./run-benchmark.sh 3000
  Or: docker run --rm -v $(pwd)/output:/app/output rdfgraphgen-benchmark --scale-factor 3000

Coherence Rationale - High:
  - scale_factor=3000 generates LARGE, COMPLETE dataset
  - Higher scale means more instances per shape
  - Each shape generates more examples with full property coverage
  - All SHACL cardinality constraints are satisfied
  - Properties defined as required (minCount 1) are all present
  - Optional properties tend to be filled (due to scale)
  - Result: DENSE, STRUCTURED data

Scale Factor Impact on Coherence:
  - Large scale_factor (3000):
    * More instances = higher probability of filling optional properties
    * Better coverage of property combinations
    * Fewer missing/null values
    * Coherence ≈ 0.7-0.85
  
  - Similar to relational database with high fill rate

Expected Output:
  - File: output/output-graph.ttl
  - Triples: ~80,000-150,000
  - File Size: ~2-4 MB
  - Instances: ~3000 (based on scale factor)

Report Output: output/benchmark_report.json

================================================================================
SHACL SHAPE CONSTRAINTS
================================================================================

LUBM SHACL Shapes Include:

1. Class Definitions:
   - University, Department, Faculty, Student, Course, Publication
   - Each has defined shape constraints

2. Property Cardinalities:
   - minCount: Minimum occurrences (required properties)
   - maxCount: Maximum occurrences

3. Datatype Constraints:
   - String properties (name, email, etc.)
   - Integer properties (age, index, etc.)
   - Date properties

4. Relationship Constraints:
   - Object properties linking classes
   - Cardinality constraints on relationships

Scale Factor Interpretation:
  - Lower scale: Only satisfy minCount constraints
  - Higher scale: Fill maxCount constraints, add optional properties
  - Coherence increases with scale (more property filling)

================================================================================
COHERENCE SCALE-FACTOR RELATIONSHIP
================================================================================

Mathematical Relationship:

Triples ≈ scale_factor × instances_per_class × properties_per_class

Property Fill Rate ≈ (minCount + scale_factor × (maxCount - minCount)) / maxCount

For LUBM:
  - High (scale=3000): Fill rate ≈ 0.8-0.95 (high coherence)
  - Low (scale=500): Fill rate ≈ 0.3-0.5 (low coherence)

Explanation:
  - SHACL defines min/max cardinalities
  - Scale factor determines how densely properties are filled
  - Larger scale = more complete property coverage
  - Directly affects coherence metric

================================================================================
CUSTOM SHACL SHAPES
================================================================================

Creating Custom Shapes:

Example SHACL Shape (Turtle format):

  @prefix sh: <http://www.w3.org/ns/shacl#> .
  @prefix ex: <http://example.org/> .

  ex:PersonShape
    a sh:NodeShape ;
    sh:targetClass ex:Person ;
    sh:property [
      sh:path ex:name ;
      sh:datatype xsd:string ;
      sh:minCount 1 ;
      sh:maxCount 1 ;
    ] ;
    sh:property [
      sh:path ex:age ;
      sh:datatype xsd:integer ;
      sh:minCount 0 ;
      sh:maxCount 1 ;
    ] .

Key Constraint Types:
  - sh:minCount: Minimum property occurrences
  - sh:maxCount: Maximum property occurrences
  - sh:datatype: Required datatype
  - sh:node: Reference to other shape (relationships)

================================================================================
IMPORTANT NOTES
================================================================================

SHACL vs SPARQL:
  - SHACL: Constraint/shape language (defines structure)
  - SPARQL: Query language (searches data)
  - RDFGraphGen uses SHACL for generation constraints

Advantages of SHACL for Generation:
  - W3C standard (vs. non-standard schema formats)
  - Explicit cardinality constraints
  - Clear property requirements
  - Validates generated data

Generation Algorithm:
  1. Parse SHACL shapes from lubm_shacl.ttl
  2. For each shape, generate instances
  3. For each instance, fill properties:
     - Required (minCount ≥ 1): Always fill
     - Optional: Fill based on scale factor
     - Cardinality limits: Respect maxCount
  4. Write to Turtle format

Scale Factor Limitations:
  - Very large scales (10000+) can use significant memory
  - Generation time scales linearly with scale factor
  - Test with smaller scale first before large runs

LUBM SHACL Specifics:
  - Defines university domain constraints
  - Required properties: type, name, etc.
  - Optional properties: descriptions, relationships
  - Coherence controlled primarily by scale factor

Typical Use Cases:
  - Testing SHACL validation implementations
  - Evaluating shape-aware query engines
  - Coherence measurement with shape constraints
  - Comparing structured vs. unstructured generation

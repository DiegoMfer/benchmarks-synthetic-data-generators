================================================================================
RUDOFGENERATE - ShEx/SHACL High-Performance Generator
================================================================================

Tool Information:
  Name: RUDOF Generate (RUst Data On the Fly)
  GitHub: https://github.com/rudof-project/rudof
  Type: High-performance ShEx/SHACL-based RDF generator
  Purpose: Fast generation of large RDF datasets from shape definitions
  Schemas: lubm.shex (ShEx format) and lubm_shacl.ttl (SHACL format)
  Location: RUDOFGENERATE/ directory
  Script: execute_benchmark_binary.py

Technical Details:
  Language: Rust (fast binary) with Python bindings
  Key Feature: Cardinality strategies (Minimum, Maximum, Random, Balanced)
  Configuration: TOML format for detailed tuning
  Output Formats: Turtle, N-Triples, RDF/XML, TriG, N3, N-Quads, JSON-LD
  Parallel: Multi-threaded generation with configurable threads

RUDOF Advantages:
  - Fastest RDF generator (Rust implementation)
  - Supports both ShEx and SHACL
  - Fine-grained cardinality control via TOML config
  - Parallel generation with batch processing
  - Excellent for large-scale benchmarks

================================================================================
HIGH COHERENCE CONFIGURATION - GENERAL PRINCIPLES
================================================================================

Cardinality Strategy: MAXIMUM with FULL property coverage
Purpose: Fill ALL properties for high coherence

TOML Configuration File: benchmark_config_high_coherence.toml

Key Parameters:

  [generation]
  entity_count = 70000            # Number of entities
  seed = 42                       # Reproducibility
  cardinality_strategy = "Maximum" # KEY PARAMETER
  property_fill_probability = 1.0 # Fill 100% of possible properties
  property_selection_strategy = "All" # Select ALL available properties
  property_count_variance = 0.0   # No variance = uniform property counts
  
  [field_generators.default]
  quality = "High"                # Complete, realistic data
  locale = "en"
  
  [generation]
  entity_distribution = "Equal"   # Uniform distribution

High Coherence Effect:
  - cardinality_strategy=Maximum:
    * Uses maximum cardinality values from schema
    * Every optional property is generated with value
    * property_fill_probability=1.0: All properties present (100%)
    * property_selection_strategy="All": All available properties selected
    * Result: COMPLETE, DENSE data
  
  - quality=High:
    * Complete field generation (all fields filled with high-quality values)
    * Realistic value generation
    * Full property coverage across all instances
  
  - entity_distribution=Equal:
    * Uniform distribution across types
    * Balanced type representation
    * No type-based sparsity
  
  Overall Result: Coherence ≈ 0.90-0.98 (Very high structure)

    ex:PersonShape {

    }

================================================================================
LOW COHERENCE CONFIGURATION - GENERAL PRINCIPLES
================================================================================

Cardinality Strategy: MINIMUM
Purpose: Fill ONLY requAXIMUM with SELECTIVE property coverage
Purpose: Fill ONLY selected properties for low coherence

TOML Configuration File: benchmark_config_low_coherence.toml

Key Parameters:

  [generation]
  entity_count = 70000            # SAME number of entities (for fair comparison)
  seed = 42
  cardinality_strategy = "Maximum" # Still Maximum, but with selective property use
  property_fill_probability = 0.25 # Only 25% of properties
  ignore_min_cardinality = true   # Allow skipping even required properties
  property_selection_strategy = "Random" # RANDOM selection (not ALL)
  property_count_variance = 0.0
  
  entity_distribution = "Equal"
  
  [field_generators.default]
  quality = "Low"                 # Minimal, basic data

Low Coherence Effect:
  - cardinality_strategy=Maximum with property_fill_probability=0.25:
    * Uses maximum cardinality values from schema BUT
    * Only 25% of available properties are generated
    * property_selection_strategy="Random": Random subset selected per instance
    * ignore_min_cardinality=true: Even required properties can be skipped
    * Result: SPARSE, INCOMPLETE data
  
  - quality=Low:
    * Minimal field generation
    * Only basic data values
    * Many properties absent across instances
  
  - property_selection_strategy="Random":
    * Each instance gets a DIFFERENT random set of properties
    * No consistent property patterns
    * High variation between instances of same type
  Overall Result: Coherence ≈ 0.15-0.35 (Very low structure)

Execution:
  Command: python3 RUDOFGENERATE/execute_benchmark_binary.py \

Expected Output:
  - File: output/generated_data.ttl
  - Entities: 70,000
  - Triples: ~175,000-250,000

  --schema FILE                # ShEx/SHACL schema file
  --entity-count N             # Number of entities (default: 100)
  --output-dir DIR             # Output directory (default: output)
  --worker-threads N           # Parallel threads (default: 4)
  --cardinality-strategy STR   # Strategy: Minimum, Maximum, Random, Balanced
  --batch-size N               # Batch size (default: 100)
  --output-format FMT          # Format: Turtle, NTriples, RDFXML, etc.
  --parallel-files N           # Parallel file writers (default: 1)
  --no-stats                   # Disable statistics file
  --compress                   # Compress output

Cardinality Strategies:

  Minimum:
    - Generates minimal data
    - Only required properties
    - Sparse datasets
    - Fastest generation
    - Coherence ≈ 0.2-0.4

  Maximum:
    - Generates maximum data
    - All optionONLY required properties
    - Skips all optional properties
    - Sparse datasets
    - Fastest generation
    - Coherence ≈ 0.2-0.4

  Maximum:
    - Generates ALL properties (if selected)
    - Can be combined with random selection for coherence control
    - Density depends on property_fill_probability
    - Coherence ≈ 0.3-0.95 (depends on fill probability)
    - Middle-ground cardinalities
    - Moderate datasets
    - Good balance
    - Coherence ≈ 0.5-0.7

Output Formats:

  Turtle (.ttl):
    - Human-readable
    - Compact format
    - Default recommended

  N-Triples (.nt):
    - Line-based format
    - Streaming-friendly
    - Larger files

  RDFXML (.rdf):
    - XML-based format
    - Legacy system support
    - Largest files

  JSON-LD:
    - JSON representation
    - Web-friendly
    - Varies in size

Worker Threads:

  --worker-threads 1: Single-threaded (slower, low memory)
  --worker-threads 4: Standard (balanced)
  --worker-threads 8: Parallel (faster, high memory)

================================================================================
SPECIAL FEATURES
================================================================================

Statistics File:
  - Auto-generated: output/generated_data.stats.json
  - Contains: entity_count, total_triples, generation_time
  - Disable with --no-stats flag

Reproducibility:
  - seed parameter ensures reproducible generation
  - Same seed produces identical data
  - Default seed: 42

Compression:
  - --compress flag compresses output
  - Supports gzip compression
  - Reduces file size ~4-5x

Batch Processing:
  - --batch-size controls batch optimization
  - Larger batches = more parallelism but more memory
  - Default: 100

Schema Format Differences:

Configuration Flexibility:

  - Entity distribution patterns
  - Field generator quality settings
  - Parallel thread configuration

Use Cases:

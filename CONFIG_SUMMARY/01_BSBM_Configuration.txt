================================================================================
BSBM - Berlin SPARQL Benchmark (E-commerce)
================================================================================

Tool Information:
  Name: Berlin SPARQL Benchmark
  Website: http://wbsg.informatik.uni-mannheim.de/bizer/berlinsparqlbenchmark/
  Source: https://sourceforge.net/projects/bsbmtools/
  Purpose: Benchmark for evaluating RDF storage systems performance
  Data Domain: E-commerce (products, vendors, offers, reviews)

Technical Details:
  Type: Java-based generator
  Output Formats: Turtle (.ttl), N-Triples (.nt), Notation3 (.n3), TriG (.trig)
  Location: BSBM/ directory
  Script: execute_benchmark.py

Generated Entities (per 100,000 products):
  - 100,000 products
  - ~2,000 producers (manufacturers)
  - ~1,000 vendors (retailers)
  - ~2 million offers
  - ~100 rating sites with ~50,000 reviewers
  - ~1 million reviews with ratings/comments
  - ~2,000 product types in hierarchy
  - ~50,000 product features
  - ~35 million triples

================================================================================
HIGH COHERENCE CONFIGURATION
================================================================================

Name: BSBM_HIGH_COHERENCE
Goal: Generate dense product data with complete attributes

Parameters:
  products: 100000                    # Number of products
  format: ttl                         # Output format (Turtle)
  forward_chaining: True              # Enable reasoning
  runs: 10                            # Number of experimental runs

Execution:
  Command: python3 BSBM/execute_benchmark.py --products 100000 --format ttl
  Or: ./run-benchmark.sh 100000
  Or: docker run --rm -v $(pwd)/output:/app/output bsbm-benchmark --products 100000

Coherence Rationale:
  - Large number of products (100,000) creates DENSE, COMPLETE product data
  - Each product has full attribute coverage (price, label, features, reviews)
  - All product properties are typically filled
  - Forward chaining enables explicit property materialization
  - Similar to TPC-H relational benchmark structure

Expected Output:
  - File: output/dataset.ttl
  - Size: ~3-4 GB
  - Triples: ~35 million
  - Triples/sec: ~100,000+

Report Output: output/benchmark_report.json

================================================================================
LOW COHERENCE CONFIGURATION
================================================================================

Name: BSBM_LOW_COHERENCE
Goal: Generate sparse product data with varied attributes

Parameters:
  products: 50000                     # Fewer products
  format: ttl                         # Output format (Turtle)
  forward_chaining: True
  runs: 10                            # Number of experimental runs

Execution:
  Command: python3 BSBM/execute_benchmark.py --products 50000 --format ttl
  Or: ./run-benchmark.sh 50000
  Or: docker run --rm -v $(pwd)/output:/app/output bsbm-benchmark --products 50000

Coherence Rationale:
  - Fewer products (50,000) creates SPARSE, VARIED product data
  - Reduced attribute coverage due to smaller scale
  - More variation in which properties appear per product
  - Note: BSBM has limited coherence control; this is baseline comparison

Expected Output:
  - File: output/dataset.ttl
  - Size: ~1.5-2 GB
  - Triples: ~17.5 million
  - Triples/sec: ~100,000+

Report Output: output/benchmark_report.json

================================================================================
OTHER CONFIGURATION OPTIONS
================================================================================

Output Format Options:
  - ttl  : Turtle (human-readable, recommended)
  - nt   : N-Triples (line-based, simpler)
  - n3   : Notation3
  - trig : TriG (named graphs)

Product Scale Examples:
  - 1,000    : ~35K triples
  - 10,000   : ~350K triples
  - 50,000   : ~1.75M triples
  - 100,000  : ~3.5M triples
  - 500,000  : ~17.5M triples
  - 1,000,000: ~35M triples

Docker Compose Usage:
  docker-compose run --rm bsbm-benchmark --products 50000
  docker-compose up

================================================================================
IMPORTANT NOTES
================================================================================

Limitations:
  - BSBM has LIMITED coherence control compared to other generators
  - Coherence is primarily affected by scale (products parameter)
  - No explicit parameter to control property sparsity
  - Included for baseline comparison purposes

Memory Requirements:
  - Small (1K products): 256MB
  - Medium (10K products): 1GB
  - Large (50K products): 4GB
  - Extra Large (100K+ products): 8GB+

Performance:
  - Fast generation (~100K triples/sec)
  - Good for testing SPARQL endpoints
  - Suitable for benchmarking query performance

Special Attributes:
  - forward_chaining: Can enable reasoning/inference during generation
  - Creates realistic e-commerce data structure
  - Includes ratings, reviews, and product hierarchies

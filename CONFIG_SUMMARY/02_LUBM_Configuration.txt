================================================================================
LUBM - Lehigh University Benchmark
================================================================================

Tool Information:
  Name: Lehigh University Benchmark
  Type: Reference benchmark for ontology-based knowledge bases
  Purpose: Evaluate SPARQL/OWL query performance on university domain data
  Ontology: univ-bench.owl (Lehigh University)
  Location: LUBM/ directory
  Script: execute_benchmark.py

Data Domain: University/Academic
  - Universities, Departments, Courses, Programs
  - Students (Graduate, Undergraduate), Faculty, Administrative staff
  - Publications, Research areas, courses taught
  - Course enrollment relationships
  - Teaching and research affiliations

================================================================================
HIGH COHERENCE CONFIGURATION
================================================================================

Name: LUBM_HIGH_COHERENCE
Goal: Generate complete university structures with full property coverage

Parameters:
  universities: 65                    # Number of universities to generate
  seed: 0                            # Random seed for reproducibility
  format: owl                         # Output format (OWL/RDF)
  runs: 10                           # Number of experimental runs

Execution:
  Command: python3 LUBM/execute_benchmark.py --universities 65 --seed 0
  Or: ./run-benchmark.sh 65
  Or: docker run --rm -v $(pwd)/output:/app/output lubm-benchmark --universities 65

Coherence Rationale:
  - LUBM inherently generates HIGHLY STRUCTURED data
  - Universities=65 generates complete faculty/student/course structures
  - Full ontology conformance: every instance has defined properties
  - Standard LUBM generation: complete department hierarchies
  - Similar to relational databases in structure

Generated Data per University (~20,659 triples per university):
  - ~1,450 students per university
  - ~750 faculty members
  - ~200 courses
  - ~500 professors + lecturers
  - ~50 departments
  - ~5,000+ publications
  - Complete publication records and research relationships

Expected Output:
  - Files: output/University0_0.owl, University1_0.owl, etc.
  - Total Triples: ~1,342,835 (65 universities)
  - Triples/sec: ~150,000+

Report Output: output/benchmark_report.json

================================================================================
CONFIGURATION OPTIONS
================================================================================

Parameters:
  -u, --universities N     # Number of universities (1-8 typical)
  -i, --index N           # Starting index for university numbering (default: 0)
  -s, --seed N            # Random seed (for reproducibility)
  -o, --ontology URL      # URL of univ-bench ontology
  -f, --format FORMAT     # Output format: "owl" or "daml"

Format Options:
  - owl  : OWL/RDF format (standard)
  - daml : DAML+OIL format

University Scale Examples:
  - 1 university  : ~20,659 triples
  - 5 universities: ~103,295 triples
  - 10 universities: ~206,590 triples
  - 50 universities: ~1,032,950 triples (use with caution)

Seed Selection:
  - seed=0: Default generation
  - seed=42: Alternative generation (different random values)
  - seed=N: Any integer for reproducible runs

================================================================================
IMPORTANT NOTES
================================================================================

Ontology Information:
  - Standard university domain ontology
  - Defines complete class and property hierarchies
  - Well-structured with clear semantics
  - Reference benchmark for RDF databases

LUBM Limitations (for Coherence Study):
  - All generated instances are INHERENTLY COMPLETE
  - Cannot easily create low-coherence variants
  - Generator fills all defined properties per instance
  - Coherence ~1 for all configurations

Why LUBM Is Reference Benchmark:
  - Produces predictable, complete data
  - Used for comparison with other generators
  - Baseline for evaluating data quality
  - Fixed schema, enabling fair comparison

Memory Requirements:
  - 1 university: 128MB
  - 5 universities: 512MB
  - 10 universities: 1GB
  - 50 universities: 5GB

Generation Time:
  - 1 university: 0.6 seconds
  - 5 universities: 3 seconds
  - 10 universities: 6 seconds
  - Highly efficient

Properties Generated per Instance Type:
  - Person: name, phone, email, publications, courses, advising relationships
  - Student: adviser, degree, degreeFrom, cardinality-based properties
  - Faculty: publications, teaches, research interests
  - Course: involves, hasPrerequisite, description, comment
  - Department: partOf, subOrganizationOf, name, comment
